Frigate Camera Driver for Control4

Displays a Frigate NVR camera in Control4 navigators with full detection event support.

Setup

This driver can be added manually or auto-created by the Frigate NVR parent driver.

Automatic (recommended)

  1. Add the Frigate NVR driver first
  2. Run Create / Relink Cameras — this driver is created automatically for each camera
  3. Move the camera to the appropriate room
  4. Optionally run Synchronize Cameras with Frigate from the NVR driver

Manual

  1. Add this driver in Composer Pro
  2. Set Frigate Host to your Frigate server IP address
  3. Set Camera Name to the exact Frigate camera name (e.g. front_door)
  4. Set Use Sub Stream to Yes for H.264 720p (recommended) or No for main stream

History

Detection events are recorded in the device history, visible in the Control4 app and on touchscreens. Loitering events are recorded with Warning severity; all others are Info.

The history is for incidents; the Timeline is for everything. Frigate's object-count, motion and zone topics all fire on every transition, so one walk up a drive produces eight rows that bury the single review entry already describing it — with a picture. Those categories default off here and go to the Timeline instead. Audio detections and camera status are discrete and rare, so they stay on.

PropertyDefaultCovers
Record Review IncidentsYesOne entry per Frigate review item, with its snapshot attached
Record Object DescriptionsYesGenAI object descriptions, with the described object's snapshot
Record Object DetectionsNoPerson, car, dog, cat and generic object detected/left
Record Motion EventsNoMotion Detected, Motion Stopped
Record Zone EventsNoZone entered, zone exited, loitering
Record Audio EventsYesSpeech, bark, scream, yell, fire alarm, glass breaking, siren, car horn, music
Record Camera StatusYesCamera online/offline, detection and recording enabled/disabled

Set any of them to Yes for the previous behaviour. Switching a category off never affects Composer programming — the event still fires, only the history row is skipped — and it does not affect the Timeline, which has its own switches.

Timeline

The Control4 Timeline agent is a separate view from the history — Navigator renders it as its own scrubbing timeline. With Timeline Reporting set to Yes (the default) it is fed from Frigate's review items: one entry per incident, rather than one per object-count transition. A single incident that produces eight Person Detected history rows produces one Timeline entry.

Where Frigate is configured with GenAI review summaries, that entry is titled with the generated summary — "Person taking out trash" rather than "person". Frigate ends a review before its summary exists and publishes the summary in a later message, so an ended review is held for Timeline Summary Wait (seconds) (45 by default) to see whether a title arrives; if none does, the detected object list is used, with any recognised face named alongside it ("Joe (person)"). Waiting does not move the entry — it is stamped with the review's own start time. Set the wait to Off if GenAI review summaries are not configured.

A GenAI summary is not always produced — the provider can fail or decline — so the object-list fallback is read about as often as the title on a busy system. It is tidied the same way the rest of the driver names objects, so it reads "Person, Car" rather than "person, car".

The Timeline need not start empty: the NVR's Send Recent Reviews to Timeline action replays recent review items from Frigate's API, each stamped with its own start time. A replay fills the Timeline only — the history records an entry at the moment it is written, with no way to backdate it, so replayed incidents would all carry the time of the replay.

Timeline Review Severity chooses which review severities qualify. The default, Alerts only, keeps the Timeline to what Frigate itself considers worth looking at.

This needs the Timeline agent (agent-timeline.c4z) to be in the project. Where it is not, reporting is a silent no-op and Timeline Status says so. Because agents are not always running when a driver loads, the driver looks again 15 seconds after startup and then at most once a minute while the agent is absent. Timeline Status reports what is actually happening: whether the agent was found, whether it accepted the last event, and whether this driver's package name matches what the agent expects.

With Timeline Object Detections set to Yes (the default) individual object detections are reported as well, alongside the review incidents — arrivals only, since a "left" entry on a timeline says nothing. The Timeline tolerates that granularity where the history does not, which is the whole point of the split: the same detection reaches the Timeline and stays out of the history.

This needs the NVR driver to be subscribed to frigate/reviews, which it is from v50 onwards. The history category switches do not apply to the Timeline; the two views are gated independently.

Detection images

With Attach Detection Images set to Yes (the default), a history entry for an incident shows the picture rather than text alone.

C4:RecordHistory has no way to carry an image, so these entries take a different route: the History agent's RECORD_HISTORICAL_EVENT returns a record uuid, and SET_METADATA_ON_RECORD attaches media_filename to it. That value is a path on the controller's own filesystem, not a URL, so the driver first fetches Frigate's snapshot (/api/events/<id>/snapshot.jpg?bbox=1&h=480) to disk. Images are written to a ring of 20 files per camera and reused, so a busy camera cannot fill the controller's disk.

Where the History agent is not in the project, or declines the record, the entry still goes through C4:RecordHistory as before — a missing agent costs the picture, not the entry. The agent is looked for again 15 seconds after the driver loads, for the same reason as the Timeline agent.

The Timeline agent itself has no image field, so Timeline entries are text. The picture lives on the matching history entry.

GenAI object descriptions

Where Frigate is configured with GenAI object descriptions, the generated text arrives well after the detection it describes. It is recorded as its own history entry of type Object Described, rather than amending an entry already written, and follows the Record Object Detections switch.

Requirements

  • Control4 OS 3.3.0 or newer
  • Frigate NVR 0.14+ with go2rtc enabled
  • go2rtc RTSP restream on port 8554
  • Frigate REST API on port 5000
  • For detection events: Frigate NVR parent driver + MQTT broker
